## MetaMask — DISPLAY-ONLY, never a signer (final decision, 2026-09-07)
- **Root cause that forced the decision:** studionet is genuinely 0-fee (gasPrice/baseFee/feeHistory all 0 — verified live), so the "not enough GEN for gas fee" MetaMask error was NOT a fee. It is MetaMask's client-side check refusing to broadcast a transaction whose `value` (the ~7 GEN report bond) exceeds the balance it reads on the account (0 GEN). studionet has no faucet for arbitrary EOAs (the Studio faucet credits Studio session accounts only), so a MetaMask account can never hold the bond → real-wallet signing cannot demo on studionet, period.
- **Resolution (user):** MetaMask is display-only, exactly like the Aegis pattern — connect shows the wallet address, it never signs. The browser identity is the sole report signer (signs offline, raw-broadcasts; studionet settles bonded writes from any 0-balance key — PROVEN live, `test-sign.mjs`).
- **Sweep:** all wallet-signing code removed from the tree — `metaMaskRequest` + the `eth_sendTransaction` branch in `tx.js` (sendWrite is Wallet-only now), `makeMetaMaskSigner` in `identity.js`, `qa-metamask.mjs` deleted. `ensureStudionet`/`STUDIONET_CHAIN` kept — the display-only connect still switches the wallet to studionet. `interlock-design-spec-v2.md` §3.4 rewritten to display-only. ## Design note — pinned read
Inter-contract calls are FORBIDDEN inside nondet blocks (linter-enforced). Evidence is the vault's own committed on-chain audit entry at the pinned index — a deterministic read every validator replays identically ⇒ inherently consensus-pinned, so NO `gl.eq_principle.strict_eq` wrapper (strict_eq is for off-chain/external sources). Documented in constitution manifest.

## studionet verified facts (drive the RAW client; full list in Claude memory `genlayer-verified-apis.md`)
- Gasless + virtual value (writes + value-bearing pays work from 0-balance accounts; `value_credited`). Reachable at https://studio.genlayer.com/api.

Every RPC — submit AND the receipt polls inside `wait_for_transaction_receipt` — is retried with backoff in `_helpers._retry` (all ops keyed by tx hash/address ⇒ idempotent re-polls). **Remove the temp diagnostic file pattern** — use `finalize_parent` + read-back instead.
